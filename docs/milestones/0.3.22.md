# v0.3.22

## 变化

- 修复活动定时任务跨轮次执行时的误判：Worker 的 queued/running 任务本轮未提交终态，但子会话仍有活动原生定时任务时，保留当前 Task 与 Conversation.activeTaskId，等待下一轮继续上报，不再立即标记 failed。
- 无活动定时任务、定时服务不可用或查询失败时仍沿用原失败结算；input_required 轮次结束仍清理等待与问题卡，手动停止、改单中断和无活动任务的定时上报行为均不变。
- 复用统一的 `hasActiveSchedule` 查询与告警路径，看板定时标记和生命周期判定使用相同的“仅活动定时任务”语义。

## 验证

- Host / Client TypeScript 检查通过，21 个测试文件共 161 项 vitest 通过。
- tsdown 四入口构建与 packaging 校验通过；发布 tgz 只含运行所需编译产物和 bundle 文件。
- GitHub Release 与私有 Verdaccio 使用同一次 `npm pack` 产物，发布后以版本、tarball 与 shasum 核对。
- 正式 tgz 装回真实 web profile，并通过指定脚本重启 3080 做启动验证。

## 兼容边界

- snapshot/RPC、Worker 工具输入、记录字段和 domain v3 均不变，旧记录无需迁移。
- 重启恢复仍会把遗留活动任务转为 interrupted，不自动恢复定时轮次中的任务执行。
- v0.3.19 起的不兼容旧会话与旧看板数据规则不变；从更老版本升级须先阅读 0.3.19 升级说明。
