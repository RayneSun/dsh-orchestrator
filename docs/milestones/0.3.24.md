# v0.3.24

## 变化

- 日程页迁移到 FullCalendar Breezy / Indigo 月历，支持 P0–P3 色条、跨天连续展示、跨周续接、选中日列表与底部未安排分组；再次点击“任务看板”会切回会话页。
- Worker 的 `task_schedule` 更名为 `task_todo`，状态工具和 `orchestrator_get` 的模型可见清单字段统一为 `todos`；snapshot、存储表和看板 RPC 继续保持 `schedules`，无需迁移数据。
- Lead、Worker 与日程相关提示统一使用“待办/日程”，模型可见 DSL、Zod 校验和宿主返回结构同步更新，不保留旧工具别名。
- 个人记忆插件被手动禁用时，Lead 跳过门控并隐藏记忆能力提示，不再因宿主空响应解析失败而阻断推理；插件存在但门控异常时仍 fail-closed。
- FullCalendar、Temporal Polyfill 及其 MIT 许可证纳入构建与发布包，packaging 校验同步覆盖第三方许可证。

## 验证

- Host / Client TypeScript 检查通过，25 个测试文件共 216 项 vitest 通过。
- tsdown 四入口构建与 packaging 校验通过；同一次 npm pack 生成 12 文件的 `cmjt-dsh-orchestrator-0.3.24.tgz`（shasum `b55ef5c28854676583bfa63df6c55403a0aed939`），供 GitHub Release 与私有 Verdaccio 使用。
- 最终 tgz 已安装到真实 Web profile，`dsh plugin --profile web list` 显示 `@cmjt/dsh-orchestrator@0.3.24`；既有会话的 11 月月历正确展示会议、北京出差、去程高铁和返程日程，选中 11 月 17 日显示北京出差与去程高铁两项，下月及“今天”导航通过。
- 宿主启动日志仍有既存 `dsh-schedule: stored version 2 != expected 1` 告警；该告警属于宿主定时插件数据版本，本版未修改其存储，也不将其表述为月历无错误。

## 兼容边界

- Worker 模型工具 `task_schedule` 无兼容别名；升级前让旧活动任务完成或停止，升级后新建 Lead / Worker 会话。
- 看板 `Snapshot.schedules`、三个 RPC 和 domain v3 存储不变；只有 Worker 工具及 Lead 工具返回的模型清单改名 `todos`。
- 个人记忆插件重新启用后需重启 Web，已按禁用状态初始化的 Lead 会话不会在运行中动态恢复记忆能力。
- v0.3.19 之前的数据升级边界不变；从旧域升级仍须备份并新建会话。
