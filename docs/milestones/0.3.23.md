# v0.3.23

## 变化

- Lead 派发提示收敛为只传细化需求与验收点，不再要求模型重复环境声明或指定 Worker 执行方法；新增按实际可见范围生成的 Worker 工具与 Skill 能力索引，减少无依据路由。
- Host 自动关联原生 schedule 与 Task，单条/批量定时消息均可按 scheduleId 更新原任务；支持 running/input_required/completed/failed 多轮上报与终态重开，不重复创建任务。
- 定时任务进度、问题作答和轮次结束结算均按来源 Task 路由；修复批量轮次唯一阻塞提问悬挂及重开后残留旧问题、答案和步骤的问题。
- outbox 使用 revision 防止旧投递回写覆盖新结果；Conversation/Task 的 `hasActiveSchedule` 始终明确返回布尔值。
- 任务新进入待操作时自动唤起未展开的看板并高亮目标；看板已可见时只高亮。Worker 被明确要求通过阻塞问题卡咨询用户，不得正文提问后直接结束。

## 验证

- Host / Client TypeScript 检查通过，24 个测试文件共 207 项 vitest 通过。
- tsdown 四入口构建与 packaging 校验通过；同一次 npm pack 生成 9 文件的 `cmjt-dsh-orchestrator-0.3.23.tgz`，供 GitHub Release 与私有 Verdaccio 使用。
- 正式 tgz 已安装到真实 web profile 并通过指定脚本重启 3080。新会话实测 running → input_required → completed：看板自动唤起、会话与任务高亮、作答后完成均正常，浏览器无 console error。

## 兼容边界

- 存储继续使用 domain v3；新增 `scheduleIds` 默认 `[]`，旧记录无需迁移。
- 四个 Worker 状态工具新增可选 `scheduleId`；批量定时消息必填，单条消息由 Host 自动识别。
- `answerTaskQuestions` 新增可选 `taskId`，旧客户端省略时保持原回退行为。
- 重启恢复仍会把遗留活动任务转为 interrupted；v0.3.19 之前的数据升级边界不变。
- 当前 web profile 启动仍有宿主既存告警：`dsh-schedule` 存储版本 2 与当前 CLI 期望版本 1 不一致。本版未修改用户数据；原生 schedule 的真实到点触发未在该 profile 验证，相关关联、批量上报与恢复逻辑由单元测试覆盖。
